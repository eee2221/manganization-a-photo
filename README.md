# 黑白漫画滤镜

**照片 → 线稿风。**干净留白底 + 连续墨线 + 可选网点。

> **先说清楚定位**：这是**滤镜**，不是风格迁移。实测证明它内部的 VGG19 风格迁移
> 环节对成品没有可测量的贡献（证据见下）。想要真正的风格迁移，用同项目的另一个
> 仓库 `neural_transfer` 里的 `style_transfer_general.py`。

```
VGG19 Gram 风格迁移（可选~~~~环节，实测几乎不影响成品）
    ↓  whiten       提亮 + 压平对比，把底色变成干净留白
    ↓  screentone   可选：45° 规则网点（漫画灰调靠网点纸，不是连续灰阶）
内容原图 → Canny / 自适应阈值 → 墨线
    ↓  正片叠底
结果（灰阶线稿风）
```

## 实测证据：为什么它不算风格迁移

### 证据一：换风格图 ≈ 换成噪声

用 5 种风格源跑同一内容图，其中两个是**对照组**（纯噪声图、纯灰块图）：

| 对比 | 平均像素差 |
|---|---|
| 真实风格图之间 | **3.12** |
| 真实风格图 vs 对照组 | **3.07** |
| 比值 | **1.02** |

换个风格图只差 **3/255 ≈ 1.2%**，而且**和"换成一张纯噪声图"的结果差不多**。
五张结果的饱和度全是 **0.0**。

### 证据二：直接关掉风格损失

把 `style_weight` 设成 0，让整个风格迁移环节消失：

| 对比 | 平均像素差 |
|---|---|
| 关掉风格损失 vs 完全不优化 | **0.03** ← 没有区别 |
| 完整流程 vs 完全不优化 | 5.08 |
| 完整流程 vs 关掉风格 | 5.11 |

**"关掉风格损失"和"完全不优化"的结果差 0.03——等于说这个环节做不做都一样。**
完整流程多出来的那 5 点差异来自 `whiten` 的色调曲线，不是风格。

（顺带：风格损失本身确实被压掉了 **99.2%**，优化是在干活的。中间输出离内容图
有 **46.78** —— 但这 46.78 全被 `whiten` 抹平了，进不了成品。）

### 证据三：换参数救不回来

试过 6 种办法，判定标准是"真风格之间差异 / 与噪声组差异 > 1.5"：

| 尝试 | 比值 |
|---|---|
| 放松白化 gamma 2.6 → 1.0 | 1.13 → 0.95 |
| 只叠线、完全不白化 | 0.64 |
| 内容层 conv_4 → conv_5 | 1.19 → 0.66 |
| 内容权重降到 0.01 | 0.81 |
| 完全不做后处理 | 0.65 |

**最好的一次 1.19，大多数在 1.0 以下。**不是参数问题，是流程架构问题：
成品的每个像素都来自内容图，风格没有通路能进去。

> **成品 ≈ 内容图 + 边缘检测 + 一条色调曲线**

## 为什么墨线不交给风格迁移

Gram 矩阵只统计**通道间相关性**，它没有"边缘"这个概念。试过各种权重和层组合，
它只能产出纹理碎块，画不出连续线条。所以墨线用 `Canny` 或 `adaptiveThreshold`
从**内容图**直接提取。

## 参数

```python
color_mode     = "gray"       # 固定灰阶。改 "content" 可得"彩色线稿"（原图配色 + 墨线）
line_method    = "adaptive"   # "canny" 只抓真实边缘；"adaptive" 密度阈值（自带网点感）
line_median    = 5            # canny 前的中值滤波核，压水面细纹
line_lo / hi   = 60 / 160     # canny 双阈值
line_dilate    = 1            # 线宽
base_flatten   = 0.55         # 底色压平程度，越大越像留白
base_floor     = 0.72         # 底色最暗下限，防止黑底压死线条
whiten_gamma   = 2.6          # 底色提亮，越大越白
use_screentone = False        # 是否叠加规则网点
tone_size      = 6            # 网点格子边长
style_delayout = True         # 自动抹掉风格图里的分格边框
net_size       = 256          # 网络输入尺寸
num_steps      = 300          # 优化轮次
snapshot_every = 0            # 0 = 不存过程快照
```

### `line_method` 怎么选

| 值 | 黑像素占比（实测） | 适用 |
|---|---|---|
| `"canny"` | **3.8%** | 照片类内容。只抓真实边缘，水面/天空的平滑渐变不受影响 |
| `"adaptive"` | **49.7%** | 本身就是线稿的输入。会把平滑渐变整片转成网点，容易糊 |

## 其它已知限制

**1. 风格图里的大面积黑白结构会被学走。** 虽然风格整体影响很小，但漫画页的分格
边框仍可能被抹到画面上。`style_delayout` 会检测长直线并用 inpaint 修补掉——实测
只改 5% 像素、风格统计只损失 4%，比中值滤波（无差别削弱 36%）精准得多。

**2. LBFGS 会间歇性失控。** 实测见过 style loss 一步之内从 14 爆到 1720，
更极端的一次从 163 爆到 20 万。脚本里有**早停保护**：损失比历史最优恶化 5 倍以上
就回滚到最优状态并停止，不会把废图当成品交出来。

**3. 显存与输入像素量近似线性。** 8GB 显卡的安全档位：
`512×512 ≈ 0.07GB` / `1600×1200 ≈ 1.1GB` / `2560×1600 ≈ 2.4GB` /
`3024×4032 ≈ 7GB（会爆）`。`image_loader` 会自动等比缩放到 `net_size` 内。

## 既然风格迁移没用，能不能删掉

**技术上可以。**按证据二，跳过整个优化环节（`num_steps = 0`）和关掉风格损失的
结果差 0.03，也就是删掉 VGG19、Gram、LBFGS 之后成品几乎不变，而运行时间能从
约 11 秒降到 1 秒以内。

**但保留着也有两个理由**：一是代码留个完整参考，二是白化要用到风格迁移输出当底色
（换成内容图自己的亮度也行，但观感会略有不同）。**要不要删是个产品决策，代码里没删。**
