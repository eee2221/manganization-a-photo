# 黑白漫画滤镜

**照片 → 线稿风。**干净留白底 + 连续墨线 + 可选网点。

**纯图像处理，不需要神经网络、不需要风格图、瞬间完成**（1600×1200 约 1 秒）。

```
内容图 → whiten 提亮压平（底色）→ 可选网点
内容图 → Canny / 自适应阈值 → 墨线
        ↓ 正片叠底
结果（灰阶线稿风）
```

## 用法

本仓库**不附带示例图片**，图片由使用者自备。

```bash
pip install numpy Pillow matplotlib opencv-python
# opencv 只用于提墨线；不装的话会自动回退到 PIL 边缘滤波（效果差一些，但能跑）

# 把图片放进 assets/，文件名按下面约定（或见下方的环境变量用法）
#   assets/content.jpg  被转换的照片

python manga_filter.py
```

也可以不改代码、不动 assets，直接指定任意路径：

```powershell
$env:CONTENT_IMAGE="D:/pics/photo.jpg"
python manga_filter.py
```

输出在 `<内容图名><run_tag>/` 下，固定三张：

```
结果.png    线稿化成片，保持原图分辨率
对比.png    输入 / 墨线 / 结果 三栏并排
输入.png    内容原图
```

## 参数

```python
color_mode     = "gray"       # "gray" 灰阶；"content" 保留原图颜色（彩色线稿）
line_method    = "canny"      # 提线方式，见下表
line_median    = 5            # 提线前的中值滤波核，压细纹
line_lo / hi   = 40 / 110     # canny 双阈值（越小抓的边缘越多）
line_dilate    = 2            # 线宽（canny 出的是 1px 线，通常要加粗）
line_dilate    = 1            # 线宽
line_close     = 3            # 闭运算接断口，让线连续。0=关闭
line_despeckle = 0            # 接断口前先去掉小于该面积的碎点。0=不去
line_alpha     = 1.0          # 墨线强度 0~1
base_whiten    = True         # 是否提亮压平底色
whiten_gamma   = 1.6          # 底色提亮，越大越白（越大暗部越空）
whiten_gain    = 1.15         # 整体增亮系数
base_flatten   = 0.30         # 底色对比压平程度，越大越像留白、暗部越白
base_floor     = 0.50         # 底色最暗下限，越大暗部越白
use_screentone = False        # 是否叠加规则网点
tone_size      = 6            # 网点格子边长
out_size       = None         # None = 保持原图；填 1024 会等比缩小
```

### `line_method` 怎么选（重要）

| 值 | 得到什么 | 适用 |
|---|---|---|
| **`"canny"`（默认）** | **1px 真线条**，配合加粗和闭运算可做到连续 | 照片、插画。想要"线条感"就用它 |
| `"adaptive"` | **黑白块面**（暗区变成实心黑块） | 只在"本来就该是纯黑白"的输入上合适 |

**关键区别：`adaptive` 是二值化，不是边缘检测。**它按"比邻域暗多少"来分黑白，
所以暗区会整片变成实心黑块 —— 那不是线，是块。实测同一张风景照：

| 配置 | 黑占比 | 连通块数 |
|---|---|---|
| adaptive b41c12 + 闭5 | 34.03% | 156 |
| **canny 40/110 + 粗2 + 闭5** | **13.09%** | **25** |
| canny 25/80 + 粗2 + 闭5 | 20.31% | 19 |

**块数 = 线条碎不碎的客观指标，越少越连续。canny 是 adaptive 的 1/6。**
而且 canny 的 13% 是真线条，adaptive 的 34% 里大半是填充块面。

### 暗部丢细节怎么调（重点）

**这是这套流程最容易踩的坑，而且根因在底色环节，不在提线环节。**

白化会把暗部整体抬亮：实测夜间插画（暗区占 71.7%）的暗区均值被抬到 **157.6**，
而原图暗区均值只有 **44.2**。所以暗部看起来"空了、发白"。

调 `whiten_gamma` / `base_flatten` / `base_floor` 这三个参数即可，实测同一张图：

| 参数组 | 暗区均值 | 效果 |
|---|---|---|
| gamma2.6 flatten0.55 floor0.72 | 157.6 | 暗部发白，场景丢失（旧默认） |
| **gamma1.6 flatten0.30 floor0.50** | **122.8** | **暗部有层次（现默认）** |
| gamma1.3 flatten0.15 floor0.35 | 107.7 | 更实，但偏灰 |
| 完全不做 whiten | 35.2 | 太黑，画面闷 |

**规律：三个值越小，暗部越实；但暗部局部对比会略降约 20%。**
三张不同类型的图（夜间插画 / 航母彩照 / 金属扫描页）都验证过，规律一致，
对"没有暗部"的图（亮区占 84%）则毫无影响。

> **补充实测**：试过在暗部做局部对比增强（CLAHE），无论参数怎么调，
> 暗区局部对比都**低于**现默认（0.14~0.16 vs 0.2058），所以没有采用。
> 也试过保边平滑（双边滤波）压暗部颗粒，但那会同时洗掉水面网点质感，方向不对。

## 为什么这里没有风格迁移

早期版本用了完整的 **VGG19 Gram 风格迁移**（300 轮 LBFGS 优化），实测它对成品
**没有可测量的贡献**，所以整个环节已被移除。开发过程中的三组独立证据：

### 证据一：换风格图 ≈ 换成噪声

用 5 种风格源跑同一内容图，其中两个是**对照组**（纯噪声图、纯灰块图）：

| 对比 | 平均像素差 |
|---|---|
| 真实风格图之间 | **3.12** |
| 真实风格图 vs 对照组 | **3.07** |
| 比值 | **1.02** |

换个风格图只差 **3/255 ≈ 1.2%**，而且**和"换成一张纯噪声图"的结果差不多**。
五张结果的饱和度全是 **0.0**。

### 证据二：直接关掉风格损失

把 `style_weight` 设成 0，让整个风格迁移环节消失：

| 对比 | 平均像素差 |
|---|---|
| 关掉风格损失 vs 完全不优化 | **0.03** ← 没有区别 |
| 完整流程 vs 完全不优化 | 5.08 |
| 完整流程 vs 关掉风格 | 5.11 |

**"关掉风格损失"和"完全不优化"差 0.03——这个环节做不做都一样。**

（顺带：风格损失本身确实被压掉了 **99.2%**，优化是在干活的。中间输出离内容图
有 **46.78** —— 但这 46.78 全被 `whiten` 抹平了，进不了成品。）

### 证据三：换参数救不回来

试过 6 种办法，判定标准是"真风格之间差异 ÷ 与噪声组差异 > 1.5"：

| 尝试 | 比值 |
|---|---|
| 放松白化 gamma 2.6 → 1.0 | 1.13 → 0.95 |
| 只叠线、完全不白化 | 0.64 |
| 内容层 conv_4 → conv_5 | 1.19 → 0.66 |
| 内容权重降到 0.01 | 0.81 |
| 完全不做后处理 | 0.65 |

**最好的一次 1.19，大多数在 1.0 以下。**不是参数问题，是流程架构问题。

### 结论与收益

```
成品 = 内容图 + 边缘检测 + 一条色调曲线
```

## 为什么墨线不交给神经网络

Gram 矩阵只统计**通道间相关性**，它没有"边缘"这个概念。实践中试过各种权重和层组合，
它只能产出纹理碎块，画不出连续线条。所以墨线用 `Canny` 或 `adaptiveThreshold`
从**内容图**直接提取。

## 已知限制

**1. 线条来自边缘检测，不是"理解"画面。** 所以纹理复杂的区域（树叶、草地、织物）
容易出一堆碎线，这是边缘检测的固有特性。

**2. `adaptive` 模式对渐变不友好。** 它比的是"比邻域暗多少"，所以会把水面、天空
这类平滑渐变整片转成网点。想要那种网点感可以用，但要用在本身就是线稿的输入上。

**3. 底色压得越平，画面越"白"。** `base_flatten` 调到 1.0 就完全没有灰调了；
想要更多层次就调小，但照片的杂乱纹理也会跟着回来。
